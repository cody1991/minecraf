# Research: 食物系统

**Feature**: 021-food-system  
**Date**: 2025-12-16

## 研究任务

### 1. 攻击判定实现方案

**决策**: 使用射线检测（Raycasting）进行攻击判定

**理由**:
- 项目已有成熟的 `Raycaster` 实现（用于方块交互）
- 射线检测与第一/第三人称视角兼容
- 性能开销低，适合 60 FPS 目标

**替代方案**:
- ❌ 球形范围检测：不够精确，无法区分朝向
- ❌ AABB 碰撞检测：需要额外的朝向计算

**实现要点**:
- 复用 `Player.getEyePosition()` 和 `Player.getLookDirection()`
- 检测射线与动物包围盒的交点
- 攻击距离限制为 3 格（与方块交互一致）

---

### 2. 食物掉落物实现方案

**决策**: 复用现有 `ItemEntity` 类

**理由**:
- `ItemEntity` 已实现完整的物理（重力、弹跳）、渲染、拾取逻辑
- 代码复用，减少开发量
- 与现有物品栏系统无缝集成

**需要扩展**:
- 在 `Block.ts` 中添加食物类型的 `BlockType` 枚举值
- 在 `TextureAtlas.ts` 中添加食物纹理
- `FoodRegistry` 已有食物类型定义，需关联到 `BlockType`

---

### 3. 进食系统实现方案

**决策**: 创建独立的 `EatingSystem` 模块

**理由**:
- 符合宪法 III（模块化游戏系统）
- 进食逻辑与生存系统解耦，便于测试和扩展
- 可独立处理进食状态、进度、中断

**状态机设计**:
```
IDLE → (按住右键 + 选中食物 + 饥饿值未满) → EATING
EATING → (进度完成) → IDLE (恢复饥饿值、消耗食物)
EATING → (松开右键 / 移动) → IDLE (取消进食)
```

**进度条 UI**:
- 类似 Minecraft 的进食粒子效果（可选）
- 或简单的进度条显示

---

### 4. 食物纹理方案

**决策**: 使用程序化生成纹理，复用现有 `TextureAtlas` 系统

**理由**:
- 项目已有程序化纹理生成（`TextureAtlas.ts`）
- 无需额外加载外部资源
- 与现有方块纹理风格一致

**食物纹理设计**:
| 食物类型 | 主色调 | 描述 |
|----------|--------|------|
| 生牛肉 | 红色 #C41E3A | 红色肉块带白色脂肪纹理 |
| 生猪排 | 粉红 #FFB6C1 | 粉色肉块带骨头 |
| 生羊肉 | 深红 #8B0000 | 深红色肉块 |
| 生鸡肉 | 浅粉 #FFDAB9 | 浅粉色鸡腿形状 |
| 生兔肉 | 浅棕 #D2B48C | 浅棕色小肉块 |

---

### 5. 音效方案

**决策**: 使用现有 `SynthAudio` 合成音效

**理由**:
- 项目使用 Web Audio API 合成音效
- 无需加载额外音频文件
- 与现有音效风格一致

**需要添加的音效**:
| 音效 | 描述 | 实现方式 |
|------|------|----------|
| 攻击命中 | 短促的打击声 | 低频噪声 + 快速衰减 |
| 拾取食物 | 清脆的拾取声 | 复用现有 `pickup` 音效 |
| 进食 | 咀嚼声 | 中频噪声 + 节奏性重复 |
| 进食完成 | 满足的吞咽声 | 低频 + 滑音 |
