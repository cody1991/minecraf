# Research: 古代地标建筑群

**Feature**: 011-ancient-landmarks  
**Date**: 2025-12-13

## 1. 建筑生成器架构模式

### Decision
采用与 `ColosseumGenerator` 相同的生成器模式：
- 每个建筑一个独立的 Generator 类
- 实现 `getBlockAt(worldX, worldY, worldZ): BlockType | null` 方法
- 通过 `LandmarkManager` 统一管理多个建筑生成器
- 在 `TerrainGenerator.getBlockTypeAt()` 中按优先级调用

### Rationale
- 现有 ColosseumGenerator 已验证此模式可行
- 模块化设计符合 Constitution 原则 III
- 每个生成器可独立测试和迭代
- 便于未来添加更多地标建筑

### Alternatives Considered
1. **单一大型生成器**: 所有建筑在一个类中 → 违反模块化原则，难以维护
2. **程序化生成**: 随机生成建筑 → 不满足"可识别的文化特征"需求
3. **预制结构文件**: 从 JSON/schematic 加载 → 增加复杂度，现有项目无此基础设施

## 2. 新方块类型需求

### Decision
添加以下新方块类型：

| 方块 | 用途 | 颜色 |
|------|------|------|
| SANDSTONE | 金字塔主体 | #d4b896 |
| SANDSTONE_CARVED | 金字塔装饰 | #c4a876 |
| RED_BRICK | 故宫红墙 | #8b2323 |
| GOLD_BLOCK | 故宫黄瓦/装饰 | #ffd700 |
| DARK_STONE | 城堡主体 | #4a4a4a |
| MOSSY_STONE | 城堡苔藓装饰 | #5a6b4a |
| TORCH | 金字塔内部照明 | #ffcc00 |

### Rationale
- 现有方块类型不足以表现三种不同文化风格
- 每种建筑需要 2-3 种特征方块以区分
- TORCH 方块用于金字塔内部导航标记

### Alternatives Considered
1. **仅使用现有方块**: STONE/BRICK/SAND → 无法区分文化风格
2. **使用颜色变体**: 同一方块不同颜色 → 现有渲染系统不支持

## 3. 平原区域扩展策略

### Decision
修改 `ChunkConstants.ts` 中的 `COLOSSEUM_FLAT_RADIUS`：
- 当前值: ~50 方块 (仅覆盖斗兽场)
- 新值: 200 方块 (覆盖整个地标区域)
- 添加 `LANDMARK_ZONE_RADIUS = 200` 常量

在平原区域内：
- 地形高度固定为 `baseHeight`
- 禁用树木和植被生成
- 保留草地表面

### Rationale
- 确保建筑放置在平坦地面上
- 避免建筑与地形冲突
- 保持与斗兽场区域的一致性

### Alternatives Considered
1. **建筑适应地形**: 建筑底部填充至地形 → 增加复杂度
2. **仅建筑位置平坦**: 每个建筑单独平坦区域 → 可能产生不自然的地形断层

## 4. 建筑布局与间距

### Decision
采用灵活布局策略：
- 斗兽场位于原点 (0, 0)
- 金字塔: 东侧 (100, 0, 0)
- 故宫: 西南侧 (-70, 0, 80)
- 城堡: 西北侧 (-70, 0, -80)

间距规则：
- 建筑中心距斗兽场: 70-100 方块
- 建筑间距: 至少 50 方块
- 所有建筑在 200 方块半径内

### Rationale
- 用户要求"灵活布局，不要隔太远"
- 三角形布局确保各方向都有建筑可见
- 间距足够避免视觉拥挤

### Alternatives Considered
1. **随机布局**: 每次生成不同位置 → 不利于玩家记忆
2. **直线布局**: 沿一个方向排列 → 其他方向空旷

## 5. 金字塔内部迷宫设计

### Decision
采用预定义迷宫结构：
- 入口: 金字塔北侧底部
- 主路径: 入口 → 下降走廊 → 大厅 → 墓室
- 分支: 2-3 条死路，长度 5-10 方块
- 导航: 主路径每隔 5 方块放置火把
- 房间: 入口厅、大走廊、宝藏室、墓室 (4 个)

### Rationale
- 用户要求"中等迷宫：有死路但用火把标记主路径"
- 预定义结构确保可探索性和可测试性
- 火把同时提供照明和导航

### Alternatives Considered
1. **程序化迷宫**: 随机生成 → 可能产生无解或过于复杂的迷宫
2. **无迷宫**: 简单走廊 → 不满足"探索感"需求

## 6. 建筑尺寸规划

### Decision

| 建筑 | 底面尺寸 | 高度 | 备注 |
|------|----------|------|------|
| 金字塔 | 50×50 | 35 | 经典 52° 角度 |
| 故宫 | 80×60 | 15 | 含围墙和主殿 |
| 城堡 | 60×60 | 25 | 含 4 座角塔 |

### Rationale
- 金字塔: 底边 50 满足 FR-004 (≥40)，高度按真实比例
- 故宫: 需要足够空间容纳对称布局和院落
- 城堡: 需要空间容纳塔楼和城墙

### Alternatives Considered
1. **更大尺寸**: 100+ 方块 → 可能影响性能
2. **更小尺寸**: 30 方块 → 无法展现建筑细节

## 7. 性能优化策略

### Decision
- 使用现有区块化渲染，无需额外优化
- 建筑方块与普通地形方块相同处理
- 金字塔内部空腔减少实际渲染方块数
- 预计新增方块数:
  - 金字塔: ~15,000 (含内部空腔)
  - 故宫: ~20,000
  - 城堡: ~18,000
  - 总计: ~53,000 方块

### Rationale
- 斗兽场约 30,000 方块，性能表现良好
- 新增建筑分布在多个区块，不会集中渲染
- 现有实例化渲染已优化大量相同方块

### Alternatives Considered
1. **LOD 系统**: 远处简化渲染 → 增加复杂度，暂不需要
2. **延迟加载**: 接近时才生成 → 可能产生加载延迟
