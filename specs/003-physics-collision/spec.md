# Feature Specification: 物理与碰撞系统 (Physics & Collision System)

**Feature Branch**: `003-physics-collision`  
**Created**: 2025-12-12  
**Status**: Draft  
**Input**: User description: "物理与碰撞 (Physics & Collision) - 重力系统、与方块的碰撞检测、跳跃功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 玩家受重力影响下落 (Priority: P1)

玩家在游戏世界中会受到重力影响。当玩家处于空中（脚下没有方块支撑）时，会自然向下坠落，直到落在固体方块上或到达世界底部。

**Why this priority**: 重力是物理系统的核心基础，没有重力系统，玩家将悬浮在空中无法正常游戏。这是所有其他物理功能的前提。

**Independent Test**: 可以通过将玩家放置在空中位置来独立测试，观察玩家是否自然下落并最终停在方块表面上。

**Acceptance Scenarios**:

1. **Given** 玩家处于空中（脚下无固体方块）, **When** 游戏运行时, **Then** 玩家持续向下移动直到接触固体方块
2. **Given** 玩家站在固体方块上, **When** 该方块被移除, **Then** 玩家开始下落
3. **Given** 玩家正在下落, **When** 玩家接触到固体方块顶面, **Then** 玩家停止下落并站立在该方块上

---

### User Story 2 - 玩家与方块碰撞检测 (Priority: P1)

玩家在移动时无法穿过固体方块。当玩家尝试走向墙壁或其他固体方块时，会被阻挡在方块边界处。碰撞检测适用于所有六个方向（上、下、前、后、左、右）。

**Why this priority**: 碰撞检测与重力同等重要，是构建可交互3D世界的基础。没有碰撞，玩家会穿过所有物体，游戏无法正常运行。

**Independent Test**: 可以通过让玩家尝试走向墙壁来独立测试，验证玩家被阻挡而非穿过墙壁。

**Acceptance Scenarios**:

1. **Given** 玩家面前有固体方块, **When** 玩家尝试向前移动, **Then** 玩家被阻挡在方块边界处
2. **Given** 玩家头顶有固体方块, **When** 玩家尝试跳跃, **Then** 玩家头部碰到方块后停止上升
3. **Given** 玩家侧面有固体方块, **When** 玩家尝试侧向移动, **Then** 玩家被阻挡无法穿过
4. **Given** 玩家在两个方块之间的缝隙中, **When** 缝隙宽度小于玩家宽度, **Then** 玩家无法通过该缝隙

---

### User Story 3 - 玩家跳跃功能 (Priority: P2)

玩家可以通过跳跃来克服障碍物或到达更高的位置。按下跳跃键后，玩家会获得向上的初始速度，然后在重力作用下逐渐减速并最终下落。

**Why this priority**: 跳跃是玩家垂直移动的主要方式，对于探索和游戏玩法至关重要，但优先级略低于基础的重力和碰撞系统。

**Independent Test**: 可以通过在平地上按跳跃键来独立测试，验证玩家能够跳起一定高度后落回地面。

**Acceptance Scenarios**:

1. **Given** 玩家站在固体方块上, **When** 玩家按下跳跃键, **Then** 玩家向上移动约1个方块高度后下落
2. **Given** 玩家已经在空中（正在下落或跳跃中）, **When** 玩家按下跳跃键, **Then** 无任何效果（不能二段跳）
3. **Given** 玩家站在地面上且头顶有方块, **When** 玩家跳跃, **Then** 玩家头部碰到上方方块后立即开始下落
4. **Given** 玩家面前有1个方块高的障碍, **When** 玩家跳跃并向前移动, **Then** 玩家能够跳上该障碍

---

### Edge Cases

- 玩家在世界边界处移动时会被阻挡，无法离开世界范围
- 玩家下落到世界底部时停止在最低有效位置，不受伤害
- 玩家同时接触多个方块时，碰撞检测正确处理所有接触面
- 玩家在方块角落处移动时，能够沿着墙壁滑动而非完全停止
- 玩家以极高速度移动时，碰撞检测仍然有效（防止穿墙）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须对玩家施加恒定的向下重力加速度
- **FR-002**: 系统必须检测玩家与所有相邻固体方块的碰撞
- **FR-003**: 系统必须阻止玩家穿过固体方块的任何表面
- **FR-004**: 系统必须在玩家接触地面时将其垂直速度归零
- **FR-005**: 系统必须响应跳跃输入，给予玩家向上的初始速度
- **FR-006**: 系统必须仅在玩家接触地面时允许跳跃
- **FR-007**: 系统必须支持玩家沿墙壁滑动（碰撞时不完全停止移动）
- **FR-008**: 系统必须限制玩家的最大下落速度（终端速度）
- **FR-009**: 系统必须正确处理玩家同时与多个方块碰撞的情况
- **FR-010**: 系统必须在世界边界处阻止玩家移动

### Key Entities

- **Player（玩家）**: 游戏中受物理系统控制的主要实体，具有位置、速度、碰撞体积（轴对齐包围盒）
- **Block（方块）**: 世界中的基本构建单元，具有位置和固体属性
- **Collision Volume（碰撞体积）**: 定义实体物理边界的抽象概念，用于碰撞检测计算
- **Velocity（速度）**: 描述玩家在三维空间中移动速度和方向的向量

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家从任意高度下落时，能在合理时间内（2秒内从10个方块高度）落到地面
- **SC-002**: 玩家在任何方向移动时，100%无法穿过固体方块
- **SC-003**: 玩家跳跃高度一致，能够稳定跳上1个方块高的障碍
- **SC-004**: 物理系统运行时游戏保持 60 FPS 稳定运行
- **SC-005**: 玩家在墙角移动时能够平滑滑动，不会卡住
- **SC-006**: 玩家在空中时无法进行二次跳跃

## Clarifications

### Session 2025-12-12

- Q: 物理系统的性能目标应该量化为多少？ → A: 保持 60 FPS 稳定运行
- Q: 玩家下落到世界底部时应该发生什么？ → A: 停止在最低有效位置（不受伤害）

## Assumptions

- 游戏世界使用标准的三维坐标系统（Y轴向上）
- 每个方块占据1x1x1的单位空间
- 玩家碰撞体积为轴对齐包围盒（AABB），宽度小于1个方块，高度约为1.8个方块（类似 Minecraft 玩家尺寸）
- 重力加速度为恒定值，不随位置变化
- 跳跃高度设计为略高于1个方块，允许玩家跳上单层障碍
- 当前阶段不考虑水、岩浆等特殊方块的物理效果
- 当前阶段不考虑玩家受伤害的机制（如摔落伤害）
