# Feature Specification: 世界存档系统

**Feature Branch**: `018-world-save-system`  
**Created**: 2025-12-13  
**Status**: Draft  
**Input**: 使用 IndexedDB 保存世界方块数据，支持多个存档槽位，存档列表管理（创建/删除/重命名），自动保存功能

## Clarifications

### Session 2025-12-13

- Q: 存档菜单的 UI 入口位置？ → A: 在现有 UI 面板（设置面板）中添加存档标签页
- Q: 世界种子是否保存？ → A: 保存世界种子，确保未探索区域地形一致

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 保存当前世界 (Priority: P1)

玩家在游戏中建造了一段时间后，希望保存当前世界的进度，以便下次继续游玩。玩家打开设置面板中的存档标签页，选择一个空槽位或覆盖现有存档，输入存档名称后保存。

**Why this priority**: 这是存档系统的核心功能，没有保存功能其他功能都无意义。玩家最基本的需求就是能够保留自己的建造成果。

**Independent Test**: 可通过创建新世界、放置若干方块、保存存档、刷新页面后加载来验证数据持久化是否成功。

**Acceptance Scenarios**:

1. **Given** 玩家正在游戏中，**When** 玩家打开存档菜单并选择"保存世界"，**Then** 系统显示存档槽位列表供选择
2. **Given** 玩家选择了一个空槽位，**When** 玩家输入存档名称并确认，**Then** 系统保存当前世界数据并显示保存成功提示
3. **Given** 玩家选择了一个已有存档的槽位，**When** 玩家确认覆盖，**Then** 系统用当前世界数据覆盖原存档

---

### User Story 2 - 加载已保存的世界 (Priority: P1)

玩家希望继续之前保存的游戏进度。玩家在主菜单或游戏内打开存档列表，选择一个存档加载，游戏恢复到保存时的状态。

**Why this priority**: 与保存功能同等重要，保存的数据必须能够被加载才有意义。

**Independent Test**: 可通过加载一个已保存的存档，验证方块位置、玩家位置是否与保存时一致。

**Acceptance Scenarios**:

1. **Given** 存在至少一个已保存的存档，**When** 玩家打开存档列表，**Then** 系统显示所有存档及其基本信息（名称、保存时间、缩略图）
2. **Given** 玩家选择了一个存档，**When** 玩家点击"加载"，**Then** 游戏加载该存档的世界数据并恢复游戏状态
3. **Given** 玩家正在游戏中，**When** 玩家加载另一个存档，**Then** 系统提示是否保存当前进度后再加载

---

### User Story 3 - 管理存档列表 (Priority: P2)

玩家希望对存档进行管理，包括重命名存档以便识别、删除不需要的存档以释放空间。

**Why this priority**: 管理功能是保存/加载的辅助功能，提升用户体验但不影响核心功能。

**Independent Test**: 可通过重命名一个存档后验证名称变化，删除一个存档后验证其从列表消失。

**Acceptance Scenarios**:

1. **Given** 存在一个已保存的存档，**When** 玩家选择"重命名"并输入新名称，**Then** 存档名称更新为新名称
2. **Given** 存在一个已保存的存档，**When** 玩家选择"删除"并确认，**Then** 该存档从列表中移除且数据被清除
3. **Given** 玩家尝试删除存档，**When** 系统弹出确认对话框，**Then** 玩家必须确认后才能删除，防止误删

---

### User Story 4 - 自动保存 (Priority: P2)

玩家在游戏过程中，系统定期自动保存当前进度，防止因意外情况（如浏览器崩溃、断电）导致进度丢失。

**Why this priority**: 自动保存是重要的安全网功能，但玩家仍可手动保存，因此优先级略低于核心功能。

**Independent Test**: 可通过开始游戏、等待自动保存间隔时间后刷新页面，验证进度是否被保留。

**Acceptance Scenarios**:

1. **Given** 玩家正在游戏中，**When** 达到自动保存间隔时间（默认 5 分钟），**Then** 系统自动保存当前进度到专用自动存档槽位
2. **Given** 自动保存正在进行，**When** 保存完成，**Then** 界面显示简短的保存成功提示（不打断游戏）
3. **Given** 玩家下次启动游戏，**When** 存在自动存档，**Then** 系统提示是否恢复上次自动保存的进度

---

### User Story 5 - 创建新世界 (Priority: P3)

玩家希望开始一个全新的游戏世界，可以选择创建新世界而不影响已有存档。

**Why this priority**: 创建新世界是扩展功能，玩家可以通过不加载任何存档来开始新游戏。

**Independent Test**: 可通过点击"创建新世界"，验证生成新的随机世界且不影响现有存档。

**Acceptance Scenarios**:

1. **Given** 玩家在主菜单，**When** 玩家选择"创建新世界"，**Then** 系统生成新的随机世界并开始游戏
2. **Given** 玩家创建新世界，**When** 世界生成完成，**Then** 该世界尚未保存，需要玩家手动保存或等待自动保存

---

### Edge Cases

- 当存储空间不足时，系统应提示用户删除旧存档或无法保存
- 当存档数据损坏时，系统应提示加载失败并建议删除该存档
- 当玩家在自动保存过程中手动保存时，应避免冲突
- 当玩家快速连续点击保存按钮时，应防止重复保存
- 当浏览器不支持 IndexedDB 时，应提示用户存档功能不可用

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 使用浏览器本地存储持久化保存世界数据
- **FR-002**: 系统 MUST 支持至少 5 个手动存档槽位
- **FR-003**: 系统 MUST 保存完整的世界方块数据（方块类型和位置）
- **FR-004**: 系统 MUST 保存玩家状态（位置、朝向）
- **FR-015**: 系统 MUST 保存世界种子，确保加载后未探索区域地形与原世界一致
- **FR-005**: 用户 MUST 能够为存档命名以便识别
- **FR-006**: 用户 MUST 能够重命名已有存档
- **FR-007**: 用户 MUST 能够删除已有存档
- **FR-008**: 系统 MUST 在删除存档前要求用户确认
- **FR-009**: 系统 MUST 支持自动保存功能，默认间隔为 5 分钟
- **FR-010**: 系统 MUST 维护一个独立的自动存档槽位
- **FR-011**: 系统 MUST 在存档列表中显示每个存档的名称和保存时间
- **FR-012**: 系统 MUST 在加载存档时恢复世界和玩家状态
- **FR-013**: 系统 MUST 在存储操作失败时向用户显示错误信息
- **FR-014**: 系统 MUST 防止保存操作的并发冲突

### Key Entities

- **存档 (Save)**: 代表一个保存的游戏状态，包含存档名称、保存时间、世界种子、世界数据、玩家状态
- **世界数据 (World Data)**: 所有已修改区块的方块信息，包含方块类型和位置
- **玩家状态 (Player State)**: 玩家的位置坐标和视角朝向
- **存档槽位 (Save Slot)**: 存档的容器，分为手动槽位和自动槽位

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家可以在 3 秒内完成保存操作（从点击保存到显示成功提示）
- **SC-002**: 玩家可以在 5 秒内完成加载操作（从点击加载到可以开始游戏）
- **SC-003**: 系统支持保存包含至少 100 个已修改区块的世界数据
- **SC-004**: 自动保存过程对游戏帧率的影响不超过 10%
- **SC-005**: 100% 的保存数据在重新加载后与保存时一致（方块位置、玩家位置无偏差）
- **SC-006**: 存档列表操作（重命名、删除）在 1 秒内完成

## Assumptions

- 玩家使用支持 IndexedDB 的现代浏览器（Chrome、Firefox、Safari、Edge）
- 单个存档的数据量不超过浏览器 IndexedDB 的存储限制（通常为数百 MB）
- 自动保存间隔 5 分钟是合理的默认值，暂不提供用户自定义选项
- 存档缩略图功能作为可选增强，不在本次核心需求范围内
- 存档不支持跨设备同步，仅保存在当前浏览器本地
